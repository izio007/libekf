## Открытая карта для проверки привязки

Сохранён участок Copernicus GLO-30 N36/W113: datasets/Copernicus_DSM_N36_W113.tif. Это модель отражающей поверхности с растительностью и сооружениями, а не гарантированно голая земля. Источник: https://copernicus-dem-30m.s3.amazonaws.com/Copernicus_DSM_COG_10_N36_00_W113_00_DEM/Copernicus_DSM_COG_10_N36_00_W113_00_DEM.tif .

Проверено по самому TIFF 29.10.2026:

- 3600 строк и 3600 столбцов, высоты float32.
- Географические координаты WGS84, EPSG 4326. Точечные отсчёты RasterPixelIsPoint.
- При нумерации от нуля: долгота = −113° + столбец/3600°, широта = 37° − строка/3600°. Добавлять половину шага к этим координатам не нужно.
- Размер файла 40 201 504 байта. SHA-256: 3778b88efb81c8f05aa483d1d5267c07c55e058f34df6603f29be0ac99289e7b.
- Тег GDAL_NODATA отсутствует. Нельзя произвольно объявить нулевую высоту или значение −32767 пропуском этого файла.

Сохранённое описание datasets/Copernicus_AWS_readme.html объясняет размер 3600 вместо 3601: у исходных плиток удалены общие восточный столбец и южная строка. Поэтому нижняя строка лежит на 36° + 1/3600°, а правый столбец — на −112° − 1/3600°.

По Product Handbook 5.0 от 29.11.2022, страницы 10 и 13, высоты заданы в метрах относительно EGM2008 (EPSG 3855). Для общего эллипсоидального выхода нужна высота геоида N: h = H_EGM2008 + N. Для проверочного участка подключена сетка N из GeographicLib EGM2008-5; принятие N=0 исказило бы вертикальную привязку. Для перехода к местным осям требуется сначала согласовать высоты, затем преобразовать географические точки на эллипсоиде; одна плоскость для всей плитки не применяется.

Указанная в руководстве вертикальная точность менее 4 м с вероятностью 90% не является готовым среднеквадратическим отклонением каждой ячейки. Модель погрешности должна учитывать участок, склон, происхождение и пространственную связь ошибок. Слои качества и локальная модель ошибок для этого участка пока не подключены.

### Сетка высоты геоида

Оригинальный архив datasets/egm2008-5.tar.bz2 получен 29.10.2026: https://downloads.sourceforge.net/project/geographiclib/geoids-distrib/egm2008-5.tar.bz2 . SHA-256: 9a57c14330ac609132d324906822a9da9de265ad9b9087779793eb7080852970. Содержит GeographicLib EGM2008 в формате PGM, 4320×2161 точка, шаг 5 угловых минут, начало 90° с.ш., 0° долготы. По заголовку архива N = −108 + 0,003 × значение пикселя, в метрах относительно WGS84. Это данные, а не установленная программа.

Для испытательного участка используется билинейная интерполяция. Заголовок данных указывает максимальную ошибку такой интерполяции 0,478 м и среднеквадратическую 0,012 м; это характеристика представления геоида, не полная погрешность карты и не гарантия точности на конкретном участке.

Служебный runtime/prepare_terrain_patch.py воспроизводит участок 21×21 точка: 36,1916667…36,2083333° с.ш., −112,5083333…−112,4916667° долготы. Исходная сетка взята с шагом в три отсчёта. Высоты геоида на участке −23,4075…−23,39136 м; полученные эллипсоидальные высоты 1858,77694…1923,78999 м. Каждая точка переводится в геоцентрические координаты на WGS84 и затем в местные оси восток–север–верх относительно центральной точки. Производные таблицы и результаты проверки находятся только в runtime.
